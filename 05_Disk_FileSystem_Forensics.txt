================================================================================
DISK & FILE-SYSTEM FORENSICS CHEAT SHEET
================================================================================

This cheat sheet covers disk partition analysis, filesystem layout extraction, and recovering files from forensic images.

================================================================================
IMAGE FORMATS & CONCEPTS
================================================================================

RAW DISK IMAGES (.dd, .img, .raw):
- Bit-by-bit copy of a physical storage device.
- Contains no metadata, headers, or compression (flat file).
- Universally compatible with all forensic tools.

EXPERT WITNESS FORMAT / ENCASE (.E01):
- Contains acquisition metadata (case numbers, timestamps, investigator notes).
- Supports data compression and encryption.
- Includes embedded MD5/SHA-1 validation hashes to verify image integrity.

================================================================================
THE SLEUTHKIT (TSK) FILE RECOVERY WORKFLOW
================================================================================

To list and extract files from a raw partition, follow this sequential workflow:

1. Examine partition layout and find the partition's starting sector offset:
   mmls image.dd
         ↓
2. Recursively list files and directories inside that partition by passing the offset:
   fls -r -p -o <offset> image.dd
         ↓
3. Locate the target file's Inode (metadata address) in the listing, and extract the file:
   icat -o <offset> image.dd <inode> > recovered_file.png

Alternatively, to recursively recover all files (both allocated and unallocated) from the partition:
   tsk_recover -o <offset> image.dd recovered_output/

================================================================================
MMLS
================================================================================
Tool / Command: mmls
Category: Disk/File-System Forensics
Purpose: Examine partition tables and determine sector layouts.
When to use: Given a physical disk image, use this to locate the start of the data partitions.
Syntax: mmls [options] image
Options:
  -t <type>  ➔ Force partition table type (e.g. gpt, dos).
  -o <offset>➔ Sector offset where partition table starts.
Example: mmls image.dd

================================================================================
FLS
================================================================================
Tool / Command: fls
Category: Disk/File-System Forensics
Purpose: List directory entries, files, and deleted files.
When to use: Browsing files and directories inside a partition.
Syntax: fls [options] image [inode]
Options:
  -r         ➔ Recursively list directories and files.
  -p         ➔ Show the full path prefix for each entry.
  -o <offset>➔ Specify partition starting sector offset (from mmls).
  -d         ➔ Display deleted entries only.
Examples:
  fls -r -p -o 2048 image.dd
  fls -d -r -p -o 4096 physical.img

================================================================================
ICAT
================================================================================
Tool / Command: icat
Category: Disk/File-System Forensics
Purpose: Recover file contents using its Inode address.
When to use: When you find a target file's Inode and need to dump the raw file contents to disk.
Syntax: icat [options] image inode
Options:
  -o <offset>➔ Specify partition starting sector offset (from mmls).
  -s         ➔ Extract slack space contents of the file.
Example: icat -o 2048 image.dd 1526 > flag.zip

================================================================================
FSSTAT
================================================================================
Tool / Command: fsstat
Category: Disk/File-System Forensics
Purpose: Display high-level filesystem configuration details.
When to use: To find superblock info, volume labels, block sizes, or OS types.
Syntax: fsstat [options] image
Options:
  -o <offset>➔ Specify partition starting sector offset.
Example: fsstat -o 2048 image.dd

================================================================================
ISTAT
================================================================================
Tool / Command: istat
Category: Disk/File-System Forensics
Purpose: Display metadata details of a specific Inode / file record.
When to use: Checking file permissions, owner UID/GID, size, and MACB timestamps.
Syntax: istat [options] image inode
Options:
  -o <offset>➔ Specify partition starting sector offset.
Example: istat -o 2048 image.dd 1245

================================================================================
ILS
================================================================================
Tool / Command: ils
Category: Disk/File-System Forensics
Purpose: List metadata structures (Inodes) and their allocation status.
When to use: Finding unallocated (deleted/free) Inodes to look for raw data chunks.
Syntax: ils [options] image
Options:
  -o <offset>➔ Specify partition starting sector offset.
  -e         ➔ List all metadata structures.
  -p         ➔ Display orphan Inodes (unallocated but still referenced).
Example: ils -o 2048 image.dd

================================================================================
TSK_RECOVER
================================================================================
Tool / Command: tsk_recover
Category: Disk/File-System Forensics
Purpose: Export and recover files from an image file system to a local directory.
When to use: To recursively extract all files (allocated, unallocated, or deleted) from a partition to a target folder on your analyst machine.
Syntax: tsk_recover [options] image output_dir
Options:
  -o <offset>➔ Specify partition starting sector offset.
  -a         ➔ Recover only allocated files.
  -e         ➔ Recover all files (allocated and unallocated).
Examples:
  tsk_recover -o 2048 image.dd recovered_files/
  tsk_recover -a -o 4096 physical.img output_dir/

================================================================================
FTK IMAGER
================================================================================
Tool / Command: FTK Imager (GUI / CLI)
Category: Disk/File-System Forensics
Purpose: Create, verify, mount, and browse forensic disk images.
When to use: When you want a GUI to browse a disk image filesystem, preview files (hex/text), export specific files, calculate hashes, or verify image integrity.
Typical GUI Workflow:
  1. File -> Add Evidence Item -> Image File -> Browse to image (.E01, .dd, .img).
  2. Expand the Evidence Tree (Evidence Item -> Partition -> File System).
  3. Browse folders and select files to preview (Hex, Text, or Rich preview tabs).
  4. Right-click on target files/folders -> Export Files to extract them.
CLI Command (ftkimager):
  ftkimager source_file destination_file [options]
CLI Options:
  --help     ➔ Show CLI help and options.
  --e01      ➔ Create EnCase E01 image format.
  --verify   ➔ Verify hashes of the image after creation.

================================================================================
AUTOPSY
================================================================================
Tool / Command: Autopsy (GUI)
Category: Disk/File-System Forensics / Automated Triage
Purpose: Automated digital forensics platform built on The Sleuth Kit.
When to use: For automated artifact parsing, keyword searches, registry parsing, timeline analysis, and browsing deleted files in a visual dashboard.
Typical GUI Workflow:
  1. Case -> New Case -> Enter case metadata.
  2. Add Data Source -> Disk Image or VM File -> Select image.
  3. Select Ingest Modules to run (e.g., File Type Identification, Keyword Search, Web Artifacts, Hash Lookup).
  4. Once analysis completes, browse results in the tree navigation panel:
     - Web History / Web Downloads
     - Deleted Files / Exif Metadata
     - Registry Analyzer / User Activity
     - Keyword Search hits
